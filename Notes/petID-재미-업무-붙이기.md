# 재미 카메라 → petID·출입/근태에 붙이기

주제 잡기가 어려울 때 보는 메모.  
**재미만 두지 말고, 지금 있는 서비스에 기능 하나 끼워 넣는 형태**로 보면 설득이 된다.  
예: petID ‘강아지 시점’ — 산책길이 개 색·소리로 바뀌는 재미 + 등록 이후에도 앱을 켜는 이유.

한 줄: **신기한 카메라가 아니라, petID가 ‘신분증 앱’에서 ‘매일 여는 앱’이 되게 만드는 모듈.**  
사람 쪽 표정은 구글 ML Kit로 읽고, 펫 신원은 우리 비문.

가장 공수가 적고 본업과 겹치는 것: **3번 촬영 게이트(눈·정면·미소)**  
가장 petID답게 포장되는 것: **1번 강아지 시점**

---

## 구글이 주는 얼굴 API — 되는 것 / 안 되는 것

ML Kit는 **누구인지(인식)** 를 하지 않는다. 얼굴이 어디 있는지, 지금 어떤 모양인지만 준다.  
신원은 회사 얼굴 엔진·비문 SDK 몫이다.

| API | 앱이 받는 값 | 업무에 쓰는 법 |
| --- | --- | --- |
| Face Detection | 웃음 확률, 왼/오른 눈 뜸, 고개 각도(Euler X/Y/Z), 눈·코·입 좌표, 프레임 간 trackingId | 미소 유도, 눈 깜빡임(살아있는 사람), 정면인지 |
| Face Mesh | 468개 3D점 | AR 가이드, 마스크, 입 모양 |
| Face Landmarker (MediaPipe) | blendshape 52개 (눈썹, 입꼬리, 턱 등) | 웃음/눈보다 훨씬 섬세한 표정 변화 |
| Gemini Nano Prompt (이미지) | “지금 불편해 보임 / 집중 중” 같은 문장 | 숫자 API가 없는 애매한 상태를 설명 |

공식 분류는 **웃음 + 눈 뜸**뿐이다. 화남·슬픔은 구글 라벨이 없다.

실무 파이프:

```
ML Kit 숫자 (smile, eyeOpen, 고개 각도)
    + MediaPipe blendshape (입꼬리, 눈썹)
    + (선택) Nano가 한 줄 설명
    → 우리 서비스 이벤트
       "정면 아님" / "눈 감음" / "협조적" / "불편해 보임"
```

출입기에서 이미 쓰는 라이브니스(눈 깜빡, 고개 좌우)가 이 API로 폰에서도 재현된다.  
사이드가 본체 기술과 같은 언어를 쓰게 된다.

화남/슬픔을 “공식 감정 인식”이라고 하면 과하다. **협조도 / 피로도 / 라이브니스** 로 부르는 게 맞다.

## 재미 → 서비스로 붙이는 맵

### 1. 강아지 시점 — petID 부가 서비스

- **재미:** 산책길이 개 색·소리로 바뀜.
- **업무:** 등록만 하고 다시 안 여는 앱에, 등록 이후에도 켜는 이유가 생김.

붙이는 위치 예:

- 등록 완료 다음 화면: “초코 눈으로 우리 집 보기”
- 보호소/병원: 대기실을 개 시점으로 보여 주고, 스트레스 포인트(형광등, 다른 개 소리) 를 리포트
- 분실 전단지: “개 키 높이(30~40cm)로 찍힌 마지막 장면” — 사람 눈높이 사진보다 탐색에 쓸모 있음

**기술:** 색 LUT + 마이크 FFT + (있으면) 기존 펫 프로필. 비문 SDK는 안 건드림.

한 줄: **신원이 비문, 일상 유지는 시점 모드.**

### 2. 앞뒤 카메라 싱크로 — 호텔·어린이집 리포트

- **재미:** 하트가 깨지는 릴스.
- **업무:** 위탁 시설이 보호자에게 보내는 데일리 케어 증빙.

```
ConcurrentCamera
  스태프 얼굴(전면) + 펫(후면)
  → ML Kit 사람: 시선이 렌즈/펫 쪽인지
  → Detector: 펫이 사람을 보는지
  → "케어 집중 12분 / 눈맞춤 34회"
```

- petID: 등록 펫과 스태프를 하루 단위로 묶어 공인된 돌봄 로그.
- 출입/근태: 창구 직원이 민원인을 실제로 보고 있는지(폰만 보는지) **동의된 트레이닝 모드**. 감시가 아님.

### 3. 사람 표정 — 비문 촬영 UX + 라이브니스

“얼굴 변화·표정을 읽는다”가 여기. petID 카메라에 보호자 얼굴이 같이 잡히는 경우가 많다.

| 감지 | 구글 API | petID에서 | 출입/키오스크에서 |
| --- | --- | --- | --- |
| 정면이 아님 | Euler Y > 18° | “코가 화면 가운데” 전에 고개부터 | 얼굴 등록 실패 감소 |
| 눈 감음 | eyeOpenProbability < 0.3 | 촬영 순간 블링크 재시도 | 사진 스푸핑 방지(깜빡임 챌린지) |
| 웃음 | smilingProbability | 프로필 사진만 미소 유도 | 환영 화면, 협조 유도 |
| 찡그림/입 다묾 | blendshape (browDown, mouthPress) | “불편하면 조명 바꾸기” 가이드 | 인증 반복 실패 → “도움 요청” 버튼 |
| 입 움직임 | Face Mesh / blendshape jawOpen | — | 따라 말하기 라이브니스 |

- **재미:** 촬영 중 보호자 표정이 캐릭터로 따라 움직임.
- **업무:** 성공률. 비문은 코 품질이고, 표정은 사람이 협조 중인지.

데모 문장:  
구글 Face Detection으로 눈 뜸·웃음을 읽고, 고개가 돌아가면 셔터를 잠근다. 비문 오촬영이 줄어든다.

### 4. 머리 위 말풍선 — 병원·창구 기록

- **재미:** 만화 자막.
- **업무:** 수의사·미용사·민원 창구에서 누가 동의했는지가 영상에 남음.

- petID: 수술/위탁 동의 — 보호자 얼굴에 “동의합니다” 말풍선 + 타임스탬프 (**녹음 동의 UI 필수**)
- 회사: 청각 접근성, 방문객 키오스크, 교육 시연

**기술:** Face Mesh(입) + Speech Recognition + trackingId로 말풍선 주인 고정.

### 5. 소멸 카메라 — 노령 펫 기록 / 보험 보조

- **재미:** 곧 사라질 것만 컬러.
- **업무:** petID 프로필의 시간축. 올해 눈·걸음 vs 작년.

- 병원 제휴: “최근 3개월 얼굴 변화”는 **의료 진단이 아니라** 보호자 내원 유도.
- 보험: 클레임용 사진이 ‘언제 찍혔고 상태가 어떤 톤인지’ 메타.

Nano 멀티모달이 “이 컷은 기록 가치가 높음”만 점수화.

### 6. 말싸움 심판 — 민원·회의가 본업

- **재미:** 부부 싸움 카드.
- **업무:** 콜센터·민원실 대화 품질. 누가 끊었는지, 목소리가 커졌는지, 욕설 구간.

출입 회사가 보안·감사 톤이면: 면담실 동의 녹음 + 온디바이스 요약(내용이 서버에 안 남음).  
**petID에는 잘 안 붙는다.** 이쪽은 사무/보안 라인.

## 표정 API만으로 당장 붙일 수 있는 것

petID 카메라 파이프(이미 CameraX)에 ML Kit 한 줄 넣는 수준.

| 기능 | 내용 |
| --- | --- |
| 촬영 게이트 | 눈 감김·옆얼굴이면 캡처 금지. 비문 재촬영 ↓ |
| 살아있는 보호자 | “눈을 한 번 깜빡이세요” — 사진 들고 등록하는 어뷰징. 출입 라이브니스와 같은 스토리. |
| 프로필 자동 셔터 | 미소 > 0.7 이고 정면이면 프로필 자동 촬영. 펫 얼굴은 기존 가이드, 사람만 구글 분류. |
| 실패 화면 분기 | 인증 실패가 반복인데 표정이 불편하면 “조명/거리 도움말”, 무표정이면 “다시 정면”. |
| 키오스크 환영 | 웃으면 문 열림이 아니라, 웃으면 안내 대사가 바뀜. 재미 + 대면 UX. |

MediaPipe blendshape까지 가면 **따라 말하기 “아/이/우”** — 얼굴 출입 단말기 데모를 폰으로 보여주는 용도.
